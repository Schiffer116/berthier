# Developing Berthier

`CLAUDE.md` is Berthier's identity, not developer docs: the repo is Berthier's home, and any agent launched here is Berthier. Vocabulary is in `CONTEXT.md`; decisions in `docs/adr/`.

## Commands

- Build: `go build -o bin/berthier ./cmd/berthier` (`bin/berthier` is gitignored and linked into `~/.local/bin`; the systemd units rebuild it on start).
- Unit tests (pure, instant): `go test ./...` (`tests/fake-herdr` stands in for Herdr in the prompt and start tests).
- E2E (real Herdr + Claude haiku, isolated `berthier-e2e-<pid>` session, so runs can overlap, ~1 min): `tests/e2e.sh` (builds the binary first).
- Lint: `go vet ./...` and `gofmt -l .` (must print nothing).
- Try against a scratch Herdr session: `BERTHIER_HERDR_SESSION=<name> BERTHIER_HOME=<tmpdir> bin/berthier <cmd>`
- Loop service: `systemctl --user {status,restart} berthier-loop`; events in `state/loop.log`, read with `berthier log [-f]`.
- Console: `systemctl --user {status,restart} berthier-dashboard`, http://127.0.0.1:8430.

## Architecture

One Go module, one binary ([ADR 0004](docs/adr/0004-go-replaces-bash-and-jq.md)). `cmd/berthier` is `app.Main`; `internal/app/run.go` dispatches `berthier <cmd>`.

- `internal/core`: pure decisions, no I/O, no clock (table-tested): `Tick`, `Usage.Fold`/`View`, `Army`, names (`CorpsName`, `Divisions`), the pane classifiers. `internal/app` and `internal/herdr` are the I/O shell around it: `app.LoadEnv` (paths and `BERTHIER_*` tunables), `herdr.Client` (Herdr CLI, `PromptAgent`), `app/store.go` (the files of `state/`, locks, `Event`), `app/cmds.go` (the commands). `internal/console` is the Console server.
- Main Loop = `Env.Loop` -> `Env.Tick` every 10s, run by `systemd/berthier-loop.service`. A tick: `herdr api snapshot` + previous `state/state.json` -> `core.Tick` (pure decisions: Revives, escalations, Corps grouping, and the whole next Grand Army State) -> the shell carries out its actions -> atomic state write. A decision that needs a pane read (deliberate exit, shell prompt, usage-limit stop) is listed under `Look`; the shell reads just those panes with the classifiers in `core/pane.go` and calls `core.Tick` again with `Obs`, so a tick is one run, or two. Only `core.Tick` writes the Grand Army State: the shell never patches it, so every decision stays unit-testable. `berthier tick` exits 3 when Herdr is unreachable.
- Events: `state/loop.log` is JSON Lines, `{ts, kind, ...fields, msg}` (`pane`, `corps`, `to`, `why`, ...), one per thing the loop decided (`core.Tick`'s `Events`) or did (`Env.Event`, from each action's `Ev` fields). `msg` is for people; code and tests match on `kind` and fields. `core.Army` gives each event its Console tag and label and skips non-JSON lines; the loop moves a pre-JSON log to `loop.log.pre-json` once.
- Console = `berthier dashboard` (`internal/console`), which refreshes `Env.ArmyView` (`core.Army`, the pure view model) every 2s in-process and pushes changes over SSE to `internal/console/index.html` (vanilla JS; its one write is `POST /api/prompt`, `PromptAgent` to a pane in the view model; `GET /api/chat` reads that Agent's Claude Code transcript, following forked sessions via `~/.claude/sessions`, else its terminal); `GET /api/skills?pane=` (`skills.go`) feeds the slash picker with that Agent's skills, commands and plugin skills. Shaping data belongs in `core/army.go`, not the page. It installs as a phone app (`app.go`: manifest, `sw.js` app-shell worker that never touches `api/*`, icons drawn in Go).
- Prompting an Agent: always `herdr.Client.PromptAgent`, never bare `herdr agent prompt`, which only types text + Enter: Claude drops that Enter while it resizes pasted image paths, leaving a draft. It confirms Claude took it (state change, or a busy Agent's box emptied) and retries Enter or the paste. Herdr also refuses multi-line `agent start` arguments, so `StartClaude` sends the Brief this way. Behind a startup dialog the Brief waits in a detached `berthier brief-after-dialog` child.
- Spoken alerts: when the user is needed (blocked `BERTHIER_SPEAK_AFTER`s, Revive given up), `tick` runs the dotfiles' `notify-user` `speak.sh` itself, once per episode, without waiting on Berthier.
- Coordination: `ask` drops a JSON file in `state/inbox/`; `tick` feeds the inbox to `core.Tick`, which picks deliveries (addressee idle, one per Agent per tick) and escalates asks stuck past `BERTHIER_ASK_STUCK` or flipping direction between two Agents `BERTHIER_PINGPONG_MAX`+ times an hour (one-way updates don't count). `notify <corps> "<text>"` (`cmdNotify`) is the same inbox for senders that are not Agents (a systemd service; no pane needed): `kind: "notify"`, from `service`, text capped at `BERTHIER_NOTIFY_MAX`, newlines kept; delivered as `[berthier notify] ...` without a reply hint, never counted for ask-stuck or ping-pong. Addressing names (`core.CorpsName`) live in `core/names.go`, shared with the commands. Ownership is `owners.md`.
- Budgets (soft, per Corps, % of the account's seven-day quota): the status line pipes its session JSON to `berthier sample` (`app/sample.go`: silent, always exits 0, one `O_APPEND` row per change of a session's cost or the week's usage (carrying the five-hour window's `five_pct`/`five_resets_at` along, never causing a row) into `state/ledger.jsonl`, deduplicated through `state/sampled/<session>`). `Env.UpdateUsage` (run by every `tick` and by `budget`, under `state/usage.lock`) folds only the ledger bytes past `offset` into `state/usage.json` with `core.Usage.Fold`: each rise in `week_pct` is split across the sessions whose cost rose since the last rise, weighted by Δcost, credited to the Corps owning the session's cwd (`core.PathMap` over `state.json` + `divisions.json`; Divisions count toward their Corps; unmapped: `other`); a new `resets_at` starts the week over; a sharp drop in `week_pct` does too, and a row lacking `five_pct` once the record has seen it (a session's first render, carrying a cached `week_pct`) counts for its cost only; a ledger past `BERTHIER_LEDGER_MAX` is moved to `ledger.jsonl.prev` once folded. `core.Tick` judges `Usage.View` against `state/budgets.json` (`berthier budget <corps> <pct>|off`): at `BERTHIER_BUDGET_WARN`% of an allowance it escalates once per week (key carries `resets_at`) to the Corps's Main Agent (Berthier without one) and speaks; at 100% it logs `budget_exhausted` and speaks once and filters that Corps and its Divisions out of Revives, usage-limit resumes and ask delivery, so nothing is lost: they go ahead when the week resets or the budget is raised. The Console's collapsible quota panel (compact on phones) draws the account's 5h/7d windows and every Corps's share of the week, against its budget where set, from `berthier army`'s `budget`. An ended week (`resets_at` past) counts for nothing until the next sample.
- Reports: `report` writes `state/reports/<claude session id>.json`; `counts` joins them with live Agents for the bar. `hook-stop` is a Claude Code Stop hook (wired globally by the dotfiles) that blocks a turn's end in a Herdr pane until the Agent has reported during it.
- Berthier = the agent whose cwd is this repo; the loop prompts escalations into its pane, and sends Berthier's own problems to `herdr notification show`.
- Revive = `herdr agent start <name> --kind claude --pane <pane> -- --resume <session>`, only when the pane survived at a shell prompt. Deliberate stops are forgotten, never Revived: a closed pane, or a clean Claude exit (it prints `Resume this session with: claude --resume <id>`; a killed process does not), read on the tick the agent vanishes and again before any Revive. A pane still holding the session with no agent listed is Herdr resuming it after a restart, not a crash: never Revived.
- Usage limits: Claude rarely continues by itself after its usage limit resets. `core.Tick` asks for each idle episode (Herdr's `state_change_seq` + `status_since`, so a turn between two ticks counts) to be read once; `core.UsageLimitReset` finds a limit stop as the last output above the input box and parses its reset time and zone; after the reset (+`BERTHIER_LIMIT_GRACE`) `tick` prompts `BERTHIER_LIMIT_PROMPT` once per episode, never twice within `BERTHIER_LIMIT_RETRY`.
- Names: Herdr forgets agent names across a restart unless it assigned them at `agent start`, and drops the name when `agent start` times out. `tick` renames an unnamed agent back to the name its session had in `state.json`.
- Divisions are the workspaces `state/divisions.json` (`Env.SetDivision`) records, as `{corps, worktree, model?}` (`model` set by `division-new`; Revive relaunches with it); that record, not the label, makes one a Division (`Divisions.IsDivision`). `division-new`/`division-done` create and remove worktree Divisions (`herdr worktree create`, default `~/.herdr/worktrees/`); `adopt` records an existing workspace. `core.Tick` nests Divisions under their Corps and routes their escalations (`to`) to the Corps's Main Agent; only a spawned Division's stop escalates.
- Runtime data is gitignored: `state/` (loop) and `notes.md` (Berthier's Notes for session continuity, imported by `CLAUDE.md`; Berthier edits the "How the user works" section of `CLAUDE.md` itself). Berthier's skills go in `.claude/skills/`.

## Gotchas

- Never experiment on the user's default Herdr session; use a named session started headlessly: `tmux new -d "env -u HERDR_ENV -u HERDR_SOCKET_PATH herdr session attach <name>"`.
- Herdr fills workspace `worktree` metadata lazily; ask git (`rev-parse --git-common-dir`) instead of trusting it.
- A Claude session with no messages is not saved and cannot be resumed.
- New directories trigger Claude's folder trust dialog (Agent shows `blocked`); trusting a parent dir covers children.
- `CLAUDE.md` `@` imports of files outside the session's cwd need interactive approval and silently drop in `claude -p`.
- Reading an idle Claude pane for more lines than its screen holds (`pane get` `scroll`: `viewport_rows` + `max_offset_from_bottom`) makes Herdr scroll it up and back to collect history (~600ms; the user sees the TUI jump). Read `--source visible` when what you need is on screen.
