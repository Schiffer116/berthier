# Developing Berthier

The repo is Berthier's home. `BERTHIER.md` is Berthier's persona. `berthier session-start` (a Claude Code SessionStart hook, registered by the dotfiles, JSON on stdin) prints it into the session at the repo root, with the Berthier Notes; a Corps's Main Agent gets its Corps's Notes; a Division or anything outside the Army gets nothing, so a Division's Agent, which reads `CLAUDE.md` like any session here, does not think it is Berthier. It never fails the session and reads Notes within `BERTHIER_SESSION_START_WAIT` (5s). `CLAUDE.md` is a pointer to this file and `CONTEXT.md` (vocabulary); decisions are in `docs/adr/`.

## Commands

- Build: `go build -o bin/berthier ./cmd/berthier` (`bin/berthier` is gitignored and linked into `~/.local/bin`; the systemd units rebuild it on start).
- Unit tests (pure, instant): `go test ./...` (`tests/fake-herdr` stands in for Herdr in the prompt and start tests).
- E2E (real Herdr + Claude haiku, isolated `berthier-e2e-<pid>` session, so runs can overlap, ~1 min): `tests/e2e.sh` (builds the binary first).
- Lint: `go vet ./...` and `gofmt -l .` (must print nothing).
- Pre-commit gate (`.githooks/pre-commit`; install: `git config core.hooksPath .githooks`, which `berthier land` also sets): rejects binaries and files over 1MB, runs vet, gofmt and the unit tests. `TestSystemdUnitsStart` builds the binary and starts every unit's `ExecStart` against `tests/fake-herdr`.
- Try against a scratch Herdr session: `BERTHIER_HERDR_SESSION=<name> BERTHIER_HOME=<tmpdir> bin/berthier <cmd>`
- Land a Division of Berthier: `berthier land <division>` (`app/land.go`): merges its branch into master (refused on conflict), runs vet/gofmt/test (failure resets master to where it was), builds `bin/berthier` aside and renames it, restarts only the services `core.LandServices` maps the changed files to, and waits until the Console answers `/` (`BERTHIER_CONSOLE_URL`) or the loop writes `state.json`, up to `BERTHIER_LAND_WAIT`. Never closes the Division.
- Loop service: `systemctl --user {status,restart} berthier-loop`; events in `state/loop.log`, read with `berthier log [-f]`.
- Console: `systemctl --user {status,restart} berthier-dashboard`, http://127.0.0.1:8430.

## Architecture

One Go module, one binary ([ADR 0004](docs/adr/0004-go-replaces-bash-and-jq.md)). `cmd/berthier` is `app.Main`; `internal/app/run.go` dispatches `berthier <cmd>`.

- `internal/core`: pure decisions, no I/O, no clock (table-tested): `Tick`, `Usage.Fold`/`View`, `Army`, names (`CorpsName`, `Divisions`), the pane classifiers. `internal/app` and `internal/herdr` are the I/O shell around it: `app.LoadEnv` (paths and `BERTHIER_*` tunables), `herdr.Client` (Herdr CLI, `PromptAgent`), `app/store.go` (the files of `state/`, locks, `Event`), `app/cmds.go` (the commands). `internal/console` is the Console server.
- Main Loop = `Env.Loop` -> `Env.Tick` every 10s, run by `systemd/berthier-loop.service`. A tick: `herdr api snapshot` + previous `state/state.json` -> `core.Tick` (pure decisions: Revives, escalations, Corps grouping, and the whole next Grand Army State) -> the shell carries out its actions -> atomic state write. A decision that needs a pane read (deliberate exit, shell prompt, usage-limit stop) is listed under `Look`; the shell reads just those panes with the classifiers in `core/pane.go` and calls `core.Tick` again with `Obs`, so a tick is one run, or a few (a read can decide a prompt whose input box is read in turn; at most four). Only `core.Tick` writes the Grand Army State: the shell never patches it, so every decision stays unit-testable. `berthier tick` exits 3 when Herdr is unreachable.
- Events: `state/loop.log` is JSON Lines, `{ts, kind, ...fields, msg}` (`pane`, `corps`, `to`, `why`, ...), one per thing the loop decided (`core.Tick`'s `Events`) or did (`Env.Event`, from each action's `Ev` fields). `msg` is for people; code and tests match on `kind` and fields. `core.Army` gives each event its Console tag and label and skips non-JSON lines; the loop moves a pre-JSON log to `loop.log.pre-json` once.
- Console = `berthier dashboard` (`internal/console`; the page composes like Messenger in the Console's own design: the Grand Army tree of Corps with their Divisions, the selected Agent's chat, and an info panel that opens from the chat header, by itself from 1320px wide unless the viewer chose), which refreshes `Env.ArmyView` (`core.Army`, the pure view model) every 2s in-process and pushes changes over SSE to `internal/console/index.html` (vanilla JS; its writes are `POST /api/prompt` (`PromptAgent` to a pane in the view model), `POST /api/budget` (`{corps, pct|null}`, `Env.SetBudget` as `berthier budget`, by dragging the budget handle on a Corps's quota bar) `POST /api/shutdown` and `POST /api/wake` (optional `{text}`, answers `{sent, skipped}`; the top bar's two-click buttons, `Env.Broadcast` as `berthier shutdown|wake`) and `POST /api/thaw` (`{pane, how}`, the Revive and Fresh Start buttons of a Frozen Agent, as `berthier revive|fresh`); `GET /api/chat` reads that Agent's Claude Code transcript, following forked sessions via `~/.claude/sessions`, else its terminal); `GET /api/skills?pane=` (`skills.go`) feeds the slash picker with that Agent's skills, commands and plugin skills. Shaping data belongs in `core/army.go`, not the page. It installs as a phone app (`app.go`: manifest, `sw.js` app-shell worker that never touches `api/*`, icons drawn in Go).
- Turn origin: every prompt Berthier sends starts with a tag (`[berthier-loop]`, `[berthier ask]`, `[berthier notify]`, `[board]`, `[berthier brief]`, `[berthier continue]`, `[berthier resume]`, `[berthier fresh]`, `[berthier shutdown]`, `[berthier wake]`, `[berthier notes]`; `core.Tag`), so the Profile tells its turns from the user's. A new kind of prompt needs its own tag in `core.OriginOf`.
- Prompting an Agent: always `herdr.Client.PromptAgent`, never bare `herdr agent prompt`, which only types text + Enter: Claude drops that Enter while it resizes pasted image paths, leaving a draft. It confirms Claude took it (state change, or a busy Agent's box emptied) and retries Enter or the paste. It never types into the user's draft: a box holding typed text (`HasDraft`: `pane read --format ansi` through `core.InputDraft`; Claude's suggested prompt after an idle `❯` is dim, SGR 2, typed text is not) refuses with `ErrDraft`, so `berthier prompt` and the Console's prompt fail with a clear message. The Main Loop holds every prompt it would send (asks, notify, `[board]`, escalations, continue/resume nudges) in `core.Tick`: each waits for a `draft` read of its pane's box, and is held while it holds a draft and until `BERTHIER_DRAFT_QUIET` seconds (20) after it was last seen holding one (a dictation pause is not done; `Agent.DraftAt`, `draft_held` event once per hold). Held means not decided: the inbox file stays, an escalation is not marked escalated, a resume or continue not recorded, so the next tick tries again. Herdr also refuses multi-line `agent start` arguments, so `StartClaude` sends the Brief this way. Behind a startup dialog the Brief waits in a detached `berthier brief-after-dialog` child.
- Spoken alerts: when the user is needed (blocked `BERTHIER_SPEAK_AFTER`s, Revive given up), `tick` runs the dotfiles' `notify-user` `speak.sh` itself, once per episode, without waiting on Berthier.
- Coordination: `ask` drops a JSON file in `state/inbox/`; `tick` feeds the inbox to `core.Tick`, which picks deliveries (addressee idle, one per Agent per tick) and escalates asks stuck past `BERTHIER_ASK_STUCK` or flipping direction between two Agents `BERTHIER_PINGPONG_MAX`+ times an hour (one-way updates don't count). `notify <corps> "<text>"` (`cmdNotify`) is the same inbox for senders that are not Agents (a systemd service; no pane needed): `kind: "notify"`, from `service`, text capped at `BERTHIER_NOTIFY_MAX`, newlines kept; delivered as `[berthier notify] ...` without a reply hint, never counted for ask-stuck or ping-pong. `shutdown [text]` / `wake` (`Env.Broadcast`, `core/broadcast.go`) are army-wide notifies: one inbox file (`kind: "shutdown"|"wake"`, `Text` the whole tagged prompt, extra text capped like notify) per Agent with a live pane, Berthier's included (`core.BroadcastTargets`), Frozen ones skipped and counted; delivered like a notify (idle-only, draft-held, one per Agent per tick) but not held by a spent budget. A wake is two-step (`Env.wake`, `Delivery.Wake`): `herdr.ClearAgent` runs `/clear` and confirms by a new session id, then the prompt carries `core.Rebuild` (last report read before the clear, Brief for a Division); an unconfirmed clear logs `wake_clear_failed`, sends nothing more, and the ask stays queued. Addressing names (`core.CorpsName`) live in `core/names.go`, shared with the commands. Ownership is `owners.md`.
- Boards (`app/boards.go`, `core/board.go`, `tests/fake-skipli`): `berthier board <corps> [--adopt <board-id>]` (also `corps-new`) records in `state/boards.json` (under `state/boards.lock`; never written by `core.Tick`) the Skipli board a Corps works from: an adopted one, else its card, named after the Corps label, on the "Grand Army" Board (found by name or created). Everything goes through `skipli-cli --env $BERTHIER_SKIPLI_ENV` (`BERTHIER_SKIPLI_BIN`; default `dev`, the one setting to flip for prod); Berthier never logs in. `Env.Tick` ends with `pollBoards`, at most every `BERTHIER_BOARD_POLL` seconds (60): `core.BoardNews` compares each Board with the ids seen on it (every card and task, so a moved task is not news); a Board with no seen record (just adopted) only seeds. A new task in a Corps's card, or a new card or task on its own Board, becomes an inbox file of `kind: "board"` that `core.Tick` delivers as `[board] new task <id> "<name>" on <board>` to the Corps's Main Agent (Berthier's pane also answers to the Corps named after its own workspace): one-way, when idle, held while it works or its Corps is over budget, never ask-stuck. Edits, moves and deletes are not delivered. Three conditions escalate once to Berthier (kept in `alerts`, re-armed when they clear): `skipli-cli` asking for a login (Session missing or expired; polling stops until it works), any other failure reading a Board, only once it has failed poll after poll for `BERTHIER_BOARD_FAIL_AFTER` seconds (300; a blip or a TLS timeout is not news; e.g. `skipli-cli` not on the unit's PATH), and a card with more than `core.BoardBigTasks` pending tasks (suggest its own Board).
- Profile ([ADR 0005](docs/adr/0005-transcripts-are-the-spend-source.md)): Spend comes from Claude Code's transcripts (`$CLAUDE_CONFIG_DIR/projects/*/<session>.jsonl` and `<session>/subagents/*.jsonl`). `Env.UpdateProfile` (`app/profile.go`, run by every `tick`, `budget` and `profile`, under `state/profile/lock`) reads only the bytes appended past each file's cursor (`state/profile/cursor.json`) and folds them with `core.FoldTranscript` (pure: one `usage` per `message.id`, turns start at a real prompt, Turn origin from Berthier's tags, Waste signal tokens, what the turn shipped: commits from `git commit` output, pull requests from `gh pr create`) into `state/profile/turns.jsonl`, one row per turn, model and pass (`Turn.Key` merges them on read; `LoadTurns` keeps the merged index in long-running processes and reads only what was appended). It keeps `BERTHIER_PROFILE_WEEKS` quota weeks (default 5); older turns move to per-session totals in `archive.json`. A cwd is placed by `core.Placer` (longest path; finished Divisions by their worktree layout); Berthier's own repo is Command overhead (`berthier`). `core.Prices` holds the per-model API prices (from the claude-api skill; an unknown model is `unpriced`). `core.Profile` is the view (`berthier profile [--waste] [--corps] [--session] [--week]`, the Console's `GET /api/profile`): Corps -> Division -> session -> turn, by model, token kind, cache hit and origin, Spend per Delivered unit, ranked Waste signals (`core.Waste`). Delivered units come from git (`app/profilecmd.go`): the first-parent history of each Corps's integration branch (of the branches its Main Agent's turns ran on, the one with the most pull requests and merges landed), credited by `core.Credit` to the Division whose turns shipped the commit or pull request (squash `(#N)`, `Merge pull request #N`, `Merge branch 'X'`, or the commit's own sha after a fast-forward); a merged branch or pull request also finishes that work (+1). Tests isolate `CLAUDE_CONFIG_DIR`; e2e sets `BERTHIER_PROFILE_SINCE`/`BERTHIER_PROFILE_PROJECTS` to read only its own transcripts.
- Budgets (soft, per Corps, % of the account's seven-day quota): the status line pipes its session JSON to `berthier sample` (`app/sample.go`: silent, always exits 0, one `O_APPEND` row per change of a session's cost or the week's usage (carrying the five-hour window's `five_pct`/`five_resets_at` along, never causing a row) into `state/ledger.jsonl`, deduplicated through `state/sampled/<session>`). The ledger only gives the account's quota. `Env.UpdateUsage` (run by every `tick` and by `budget`, under `state/usage.lock`, after `UpdateProfile`) folds only the ledger bytes past `offset` into `state/usage.json` with `core.Usage.Fold`: each rise in `week_pct` is split across the Spend of the Profile rows since the previous rise, by Corps (Divisions count toward their Corps; Command overhead is `berthier`; a rise no Spend explains: `other`); a new `resets_at` starts the week over; a sharp drop in `week_pct` does too, and a row lacking `five_pct` once the record has seen it (a session's first render, carrying a cached `week_pct`) counts for its cost only; a record without `source: transcripts` is refolded from the whole ledger once; a ledger past `BERTHIER_LEDGER_MAX` is moved to `ledger.jsonl.prev` once folded. `core.Tick` judges `Usage.View` against `state/budgets.json` (`berthier budget <corps> <pct>|off`): at `BERTHIER_BUDGET_WARN`% of an allowance it escalates once per week (key carries `resets_at`) to the Corps's Main Agent (Berthier without one), with that Corps's top Waste signals, and speaks; at 100% it logs `budget_exhausted` and speaks once and filters that Corps and its Divisions out of Revives, usage-limit resumes and ask delivery, so nothing is lost: they go ahead when the week resets or the budget is raised. Once a new quota week is an hour old, `core.Tick` asks Berthier once (`optimize`) to spawn an optimizer Division that proposes environment changes from last week's Profile as an Artifact for the user's approval. The Console's collapsible quota panel (compact on phones) draws the account's 5h/7d windows and every Corps's share of the week, against its budget where set, from `berthier army`'s `budget`; its Profile view (top bar tab, `#profile`) draws `api/profile` and takes the quota panel along. An ended week (`resets_at` past) counts for nothing until the next sample.
- Quota guard (`core/quota.go`): when the five-hour or seven-day window first reaches `BERTHIER_QUOTA_GUARD_PCT` (90), `core.Tick` logs `quota_guard`, speaks once, and sends the `quota` broadcast (`[berthier quota]`, a short Notes handoff, `core/broadcast.go`) to each idle non-Frozen, draft-free Agent once per window (keys carry `resets_at` and the pane); working Agents get it on their next idle in the same window.
- `last <pane>`: the Agent's latest assistant text via the Console's transcript reader (`console.GetAgent`, `Transcripts.Path`/`Last`), so reading a finished Agent never scrolls its pane.
- Demos: `demo <url> [label]` (`cmdDemo`, no-op outside a Herdr session like `report`) keeps each Agent session's hosted demos/previews newest-first in `state/demos/<session>.json` (http(s) only, 10 max, same URL updated in place; `--clear [url]`, `--list`); `core.Army` puts them on each `AgentView` as `demos` for the Console's info panel.
- Reports: `report` writes `state/reports/<claude session id>.json`; `counts` joins them with live Agents for the bar. `hook-stop` is a Claude Code Stop hook (wired globally by the dotfiles) that never blocks: a turn that ends in a Herdr pane without a report during it gets one written for it (`autoReport`: the final message's first sentence, `needs you:` when it asks the user something, 120 characters).
- Berthier = the agent started in the repo root (it gets `BERTHIER.md` from the SessionStart hook); the loop prompts escalations into its pane, and sends Berthier's own problems to `herdr notification show`.
- Launch flags (`claudeFlags`, used by every start, Revive and Fresh Start): `--model` (a Main Agent with none runs on `BERTHIER_CORPS_MODEL`, opus); `--disallowedTools Artifact` for a Division unless it was spawned with `--artifact`. Berthier's persona comes from the SessionStart hook (`berthier session-start`), not a flag.
- Revive = `herdr agent start <name> --kind claude --pane <pane> -- --resume <session>` (plus its launch flags), only when the pane survived at a shell prompt, and by itself only while resuming is cheap: the session's last API call less than `BERTHIER_CACHE_WARM` seconds ago (3300; Claude Code's cache TTL is an hour) or its context under `BERTHIER_FROZEN_MIN` tokens (50000), read from its transcript (`core.CacheOf`: the last real call, not Claude's synthetic limit stop). Otherwise the Agent is Frozen (`Agent.Frozen`, `frozen` event): never Revived by itself, its asks, notifies and `[board]` messages held in the inbox (never ask-stuck), not a Main Agent its Divisions escalate to, one spoken Escalation to Berthier per episode (several at once go as one prompt; Berthier Frozen itself: to the user). The same goes for a usage-limit resume. A Frozen Division gets a Fresh Start by itself, once per episode, when `state/briefs/<name>.md` exists and `git status --porcelain` in its worktree is empty (committed WIP is clean; `Obs.Auto` = `core.AutoCheck`, read by `Env.autoCheck`, decided by `AutoCheck.Verdict`; events `auto_fresh`, `auto_fresh_refused`); otherwise it stays Frozen, `Frozen.Auto` records the refusal and the Escalation says why. Main Agents and Berthier never. The user chooses: `berthier revive|fresh <pane>` or the Console's buttons (Revive shows the context tokens and `core.Cache.ReviveUSD`, the context priced as a cache write; Fresh Start shows `BERTHIER_FRESH_EST_TOKENS` (60000) priced the same) drop a file in `state/thaw/` that the next `core.Tick` decides (the command runs that tick itself and prints the outcome): Revive resumes it anyway (a usage-limited one gets the resume prompt); Fresh Start (`Env.freshStart`) ends a still-running Claude (two Ctrl-C), forgets the old session and starts a new one in the pane on the model the transcript names, prompted with `core.FreshPrompt`: `berthier notes`, the Board, its last report (quoted from `state/reports`) and git; a Division also gets its Brief again (`division-new` keeps it in `state/briefs/<name>.md`). The user prompting a usage-limited Frozen Agent themselves thaws it. Deliberate stops are forgotten, never Revived: a closed pane, or a clean Claude exit (it prints `Resume this session with: claude --resume <id>`; a killed process does not), read on the tick the agent vanishes and again before any Revive. A pane still holding the session with no agent listed is Herdr resuming it after a restart, not a crash: never Revived.
- Restart resume: Herdr resumes every session after a machine/Herdr restart, but idle, even Agents cut off mid-turn. A tick that finds `state.json` older than `BERTHIER_RESTART_GAP` (loop down or Herdr unreachable: `tick` exits 3 without writing state) remembers every Agent that was `working` in it, by session, under `interrupted` in the state, because the first tick overwrites the state and Herdr relists agents over several ticks (entries expire after `BERTHIER_RESTART_WAIT`). A remembered session listed as an agent and held idle for `BERTHIER_RESTART_SETTLE` (Herdr first lists the stale status, then relaunches Claude) is read once: `core.TranscriptInterrupted` (fed by `app.transcriptInterrupted`) says whether its transcript's last message is unfinished (tool result, task notification, unanswered tool call; not a finished assistant turn, not the user's own interrupt). If so `tick` prompts `BERTHIER_RESTART_PROMPT` once (`continued` event); either way it is forgotten, as is one that is working or blocked again. Agents idle or blocked before the gap, and deliberately exited ones (never relisted), are not prompted; a Corps over budget stays remembered until it is not.
- Usage limits: Claude rarely continues by itself after its usage limit resets. `core.Tick` asks for each idle episode (Herdr's `state_change_seq` + `status_since`, so a turn between two ticks counts) to be read once; `core.UsageLimitReset` finds a limit stop as the last output above the input box and parses its reset time and zone; after the reset (+`BERTHIER_LIMIT_GRACE`) `tick` prompts `BERTHIER_LIMIT_PROMPT` once per episode, never twice within `BERTHIER_LIMIT_RETRY`.
- Idle Notes: `core.Tick` asks an idle, non-Frozen Agent once per idle episode (`Agent.NotesAsked`, keyed like usage-limit reads: `state_change_seq:status_since`) `[berthier notes] berthier notes; update them if stale, else reply ok` when its session's last API call is `BERTHIER_CACHE_WARM`-`BERTHIER_NOTES_LEAD` (300; 0 = off) seconds old and still warm (`Cache.Warm`), i.e. just before it would go cold, and its Corps's Notes are stale. Stale = not set since that call: `berthier notes --set` records the time per Corps in `state/notes-set.json` (`TickIn.NotesSet`; a set that finds them unchanged counts), no store read. The transcript (`cache` look) is read only once the episode is within 2 minutes of the window. Delivered like any held prompt (draft-held, idle-only, a Corps over budget filtered); the prompt is marked sent when decided, so a failed one (`notes_ask_failed`) is not retried that episode. Event `notes_asked`.
- Names: Herdr forgets agent names across a restart unless it assigned them at `agent start`, and drops the name when `agent start` times out. `tick` renames an unnamed agent back to the name its session had in `state.json`.
- Divisions are the workspaces `state/divisions.json` (`Env.SetDivision`) records, as `{corps, worktree, model?, artifact?}` (`model` and `artifact` set by `division-new`; Revive relaunches with them); that record, not the label, makes one a Division (`Divisions.IsDivision`). `division-new`/`division-done` create and remove worktree Divisions (`herdr worktree create`, default `~/.herdr/worktrees/`); `adopt` records an existing workspace. `core.Tick` nests Divisions under their Corps and routes their escalations (`to`) to the Corps's Main Agent; only a spawned Division's stop escalates.
- Notes (`app/notes.go`): `berthier notes [<corps>]` prints a Corps's Notes (default: the caller's Corps; a Division's is its Corps's), `--set -` replaces them from stdin, refused while they changed since this reader (Claude session, else pane) last read them (`state/notes-read.json`, under `state/notes.lock`), capped at `BERTHIER_NOTES_MAX` bytes (32768; Skipli takes a change of up to 128KiB). The store is Army-wide, `BERTHIER_NOTES_STORE` (only `skipli`): the description of the Corps's card on the Grand Army Board, or of a card named `notes` at the top of its own Board (created on the first set; never Board news). Only `berthier` touches the store.
- Runtime data is gitignored: `state/` (loop). Berthier edits the "How the user works" section of `BERTHIER.md` itself. Berthier's skills go in `.claude/skills/`.

## Gotchas

- Tests that run git must never reach the real repo: a hook exports `GIT_DIR`/`GIT_INDEX_FILE`, so the pre-commit gate unsets them and `internal/app`'s `TestMain` drops them too. New test packages that run git need the same.
- Never experiment on the user's default Herdr session; use a named session started headlessly: `tmux new -d "env -u HERDR_ENV -u HERDR_SOCKET_PATH herdr session attach <name>"`.
- Herdr fills workspace `worktree` metadata lazily; ask git (`rev-parse --git-common-dir`) instead of trusting it.
- A Claude session with no messages is not saved and cannot be resumed.
- New directories trigger Claude's folder trust dialog (Agent shows `blocked`); trusting a parent dir covers children.
- Reading an idle Claude pane for more lines than its screen holds (`pane get` `scroll`: `viewport_rows` + `max_offset_from_bottom`) makes Herdr scroll it up and back to collect history (~600ms; the user sees the TUI jump). Read `--source visible` when what you need is on screen.
